# Table

Table viser data i rader og kolonner, så brukeren kan finne, sammenligne og forstå
informasjon. Tabellen kan sorteres, rader kan velges eller ekspanderes, og over tabellen kan
du ha søk, filtre og handlinger.

## Egnet til

- Informasjon med en tydelig struktur av rader og kolonner
- Verdier brukeren skal sammenligne på tvers av flere elementer, som beløp, datoer og status
- Større mengder informasjon som brukeren skal skanne
- Data der brukeren trenger sortering, søk, filtrering eller valg av rader

## Uegnet til

- Få og enkle opplysninger som ikke skal sammenlignes. Bruk heller [Row](./row)
- Innhold uten sammenheng mellom rader og kolonner
- Elementer med mye ulik informasjon eller en visuell presentasjon. Bruk heller [Card](./card)
- Å finne og åpne ett element på en liten flate, når kolonnene ikke skal sammenlignes. Bruk heller en liste med [Row](./row)

## Bruk

Tabellen står i et kort med valgfri tittel over. Tittelen gir også tabellen navn. Høyrejuster
kolonner med tall som skal sammenlignes, så justeres overskriften og cellene i kolonnen likt.

## Eksempler

### Sortering

En sorterbar kolonne har en knapp i overskriften. Første klikk sorterer stigende, neste
synkende, og det tredje fjerner sorteringen. Den sorterte kolonnen har `aria-sort`.

I HTML sorterer tabellen radene selv, etter celleteksten eller `data-sort-value`. Beløp med
mellomrom eller punktum som tusenskille, komma, fortegn og valuta (`kr`, `NOK`, `,-`) sorteres som
tall, og det samme gjør datoer på formen dd.mm.åååå og åååå-mm-dd, med eller uten klokkeslett. Tall
står før tekst, og tomme celler og «–» står sist, i begge retninger.
Alt annet sorteres som tekst, så bruk `data-sort-value` når celleteksten ikke sier nok, for
eksempel «I går».

Henter du data fra en tjeneste, setter du `data-sort-controlled` på `ix-table`. Da sorterer ikke
tabellen selv, men sender `sort-request` med neste sortering. Du sorterer, setter `aria-sort` på
kolonnen du sorterte og fjerner det fra de andre. I React er tabellen alltid styrt slik: du
sorterer dataene ut fra `onSortChange`, og `sort` gir `aria-sort`.

Rekkefølgen endres uten at fokus flytter seg, så tabellen leser opp hva som skjedde, for eksempel
«Sortert etter Beløp, synkende» og «Sortering fjernet». Du skriver tekstene, med `{column}` der
kolonnens navn skal stå.

```tsx live
function Transaksjoner() {
  const [sort, setSort] = useState({ key: 'dato', direction: 'descending' });
  const rader = [
    { id: 't1', dato: '2026-11-06', mottaker: 'Matbutikken', type: 'Kortkjøp', belop: -684.5 },
    { id: 't2', dato: '2026-11-05', mottaker: 'Strømleverandør', type: 'AvtaleGiro', belop: -1245 },
    { id: 't3', dato: '2026-11-04', mottaker: 'Kafé Torget', type: 'Kortkjøp', belop: -89 },
  ];
  const sortert = sort
    ? [...rader].sort((a, b) => {
        const retning = sort.direction === 'ascending' ? 1 : -1;
        if (sort.key === 'belop') return (a.belop - b.belop) * retning;
        return String(a[sort.key]).localeCompare(String(b[sort.key]), 'nb') * retning;
      })
    : rader;
  const kroner = new Intl.NumberFormat('nb-NO', { minimumFractionDigits: 2 });

  return (
    <Table
      title="Transaksjoner"
      sort={sort}
      onSortChange={setSort}
      sortLabels={{
        ascending: 'Sortert etter {column}, stigende',
        descending: 'Sortert etter {column}, synkende',
        none: 'Sortering fjernet',
      }}
    >
      <Table.Header>
        <Table.HeaderCell sortKey="dato">Dato</Table.HeaderCell>
        <Table.HeaderCell sortKey="mottaker">Mottaker</Table.HeaderCell>
        <Table.HeaderCell>Type</Table.HeaderCell>
        <Table.HeaderCell sortKey="belop" align="end">Beløp</Table.HeaderCell>
      </Table.Header>
      <Table.Body>
        {sortert.map((t) => (
          <Table.Row key={t.id}>
            <Table.Cell>{t.dato.split('-').reverse().join('.')}</Table.Cell>
            <Table.Cell>{t.mottaker}</Table.Cell>
            <Table.Cell>{t.type}</Table.Cell>
            <Table.Cell>{kroner.format(t.belop)}</Table.Cell>
          </Table.Row>
        ))}
      </Table.Body>
    </Table>
  );
}
```

### Multi select med toolbar

Checkboxen i headeren velger eller opphever alle rader, og viser delvis valgt når bare noen er
valgt. Når noe er valgt, viser toolbaren antallet og handlingene for utvalget. Søk og filter
står der hele tiden. Teksten i `data-field="selected-label"` leses opp etter hvert valg, så
skjermleserbrukere også får vite hvor mange rader som er valgt.

Utvalget gjelder på tvers av søk, filtre og sider. En valgt rad som filtreres bort eller havner
på en annen side, er fortsatt valgt, og den er valgt igjen når den vises. Antallet teller alle som
er valgt. «Velg alle» velger radene som vises, og valg utenfor står. Vil du tømme utvalget, for
eksempel etter «Godkjenn», bruker du `clearSelection()` i HTML og setter `selectedKeys` til `[]`
i React.

### Ekspanderbare rader

Knappen i første kolonne åpner og lukker innholdet rett under raden. Klikk på raden gjør det
samme. Innholdet kan ha tekst, Tag, lenker og knapper.

Skjuler du en rad med `hidden`, for eksempel med et filter, skjules innholdet under den også, og
det kommer tilbake åpent når raden vises igjen.

I HTML legger du innholdet i `.ix-table__expanded-content` inne i cellen. Det er den som vokser
fram når raden åpnes. Uten den åpnes og lukkes raden uten overgang. Overgangen krever
`interpolate-size`, som Chrome og Edge har. I andre nettlesere hopper raden åpen og lukket.

## Retningslinjer

### Velg variant ut fra hva brukeren skal gjøre med dataene

| Variant | Bruk når |
|---------|----------|
| Basic | Tabellen skal vise informasjon, uten valg eller utvidelse av rader |
| Sortable | Sortering hjelper brukeren med å finne eller sammenligne. Kan kombineres med alle de andre |
| Single select | Brukeren skal velge én rad blant flere alternativer |
| Multi select | Brukeren skal velge flere rader og gjøre noe med utvalget |
| Expandable | En rad har tilleggsinformasjon som er nyttig ved behov, men ikke trenger å ta plass hele tiden |

Ikke legg informasjon som brukeren trenger for å sammenligne radene i den ekspanderte delen.
Den hører hjemme i en kolonne.

### Gjør bare kolonner som hjelper brukeren sorterbare

Sorter på dato, beløp eller navn når det hjelper brukeren å finne noe. En kolonne med status
eller fritekst blir sjelden lettere å bruke av å kunne sorteres. Er data sortert fra
tjenesten, sett `aria-sort` på kolonnen fra start, så brukeren ser hvilken rekkefølge radene
har.

### Hold cellene enkle å skanne

En celle kan inneholde tekst, tekst med beskrivende tekst, [Tag](./tag), lenke,
[Button](./button) eller [InteractiveIcon](./interactive-icon). Hold strukturen lik nedover i
hver kolonne. Trenger en rad flere handlinger eller mye tekst, flytt det til en ekspandert rad
eller en egen visning. Kuttes tekst og hele teksten er viktig, må den kunne nås uten pekeren.
Tooltip kan vise den, men skal ikke være eneste vei.

### Høyrejuster tall som skal sammenlignes

Venstrejuster tekst. Høyrejuster beløp, antall og prosent, så sifrene står under hverandre.
Overskriften følger justeringen i kolonnen. Handlinger i en egen kolonne kan også
høyrejusteres, så de står på samme sted i hver rad.

### Vis bare funksjonene tabellen trenger

Toolbaren kan ha søk, filtre og handlinger, men en tabell trenger sjelden alle tre. Vis de
viktigste handlingene direkte, og samle resten under én knapp for flere handlinger, særlig når
plassen er liten. En toolbar med bare handlinger for utvalget står tom når ingenting er valgt,
så ha minst én ting som alltid vises.

### Vis antallet og handlingene når rader er valgt

Når brukeren har valgt rader, vis hvor mange som er valgt og handlingene som gjelder dem. Søk
og filtre skal fortsatt kunne brukes, så brukeren kan finne flere rader å velge. Antallet teller
også valgte rader som ikke vises nå. Skriv det i teksten når det kan overraske, for eksempel
«5 valgt, 2 på andre sider», så brukeren vet hva en handling gjelder.

### Behold søk og filtre når det ikke blir treff

Vis meldingen i radområdet og la søket, de aktive filtrene og kolonneoverskriftene stå. Si hva
som skjedde og hvordan brukeren kommer videre: «Ingen treff. Prøv et annet søk eller endre
filtrene.»

### Velg loading etter hvor mye av tabellen som er kjent

Er kolonnene kjent, som ved søk, filtrering, sortering, paginering og oppdatering, behold
overskriftene og vis loading i radområdet. Lastes hele tabellen og kolonnene er ukjente, bruk
skeleton. La skeleton ligne tabellen som kommer, uten å se ut som ekte data.

### La tabellen rulle på små flater

Behold kolonnene når brukeren trenger å sammenligne på tvers av rader, og la tabellen rulle
vannrett. Ikke skjul kolonner bare fordi plassen blir mindre. Skal noen kolonner bort på små
flater, må det være et bevisst valg ut fra innholdet. Fest første kolonne når den trengs for å
vite hvilken rad brukeren ser på, eller handlingskolonnen når handlingene må være tilgjengelige
hele tiden, men ikke begge. Skal brukeren mest finne og åpne ett element, er en liste med
[Row](./row) ofte bedre enn en tabell som ruller.

### Designvalg

Checkbox, radio og ekspanderingsknappen er 24 px, som ellers i Indeks, ikke 18 px som i
Figma. Med 18 px ville «velg alle» i headeren stått så nær sorteringsknappen ved siden av at
den ikke når målstørrelsen i WCAG 2.2 (2.5.8). Det er ikke et krav hos oss, men vi følger det
der det er enkelt.

En valgt rad har samme farge ved hover og active som en rad som ikke er valgt, slik Figma
viser. Det avviker fra akseptansekriteriet om at hover, active og valgt skal kunne skilles når
de gjelder samtidig. Hvilken rad som er valgt, vises likevel av checkboxen eller radioen, så
det formidles ikke med farge alene.

Tettheten bruker `data-density`, som skalerer spacing-tokenene i hele systemet. Table har ingen
egne regler for tetthet.

## Universell utforming

### Hva du selv må sørge for

- Gi tabellen et navn med tittelen, eller `aria-label` når den ikke har tittel. Velg
  overskriftsnivå ut fra overskriften over tabellen.
- Skriv en overskrift i hver kolonne. En kolonne med bare ikoner får skjult tekst, for
  eksempel «Handlinger».
- Gi hver kontroll et navn som sier hvilken rad den gjelder: «Velg Strømleverandør», «Vis
  detaljer for Boliglån», «Flere valg for Fjordkraft AS».
- Gi søk og filtre i toolbaren et navn som sier hva de søker i eller filtrerer på. Placeholder
  er ingen ledetekst.
- Fortell skjermleserbrukere hva søk, filter og sortering endret, med en statusmelding som
  «12 treff».
- Sorterer du selv i HTML med `data-sort-controlled`, setter du `aria-sort` på kolonnen selv.
- Send inn alle tekster på brukerens språk, også tekstene som leses opp når sorteringen endres.
  Tabellen har ingen standardtekster.

### Hva komponenten gjør automatisk

- Kolonneoverskriftene har `scope="col"`, så hver celle leses med sin overskrift.
- Den sorterte kolonnen har `aria-sort`, og sorteringsknappen har overskriften som navn.
- Valgt rad kan identifiseres via checkboxen eller radioen. «Velg alle» viser delvis valgt.
- Ekspanderingsknappen har `aria-expanded` og peker på innholdet med `aria-controls`.
- Ruller tabellen, kan rulleområdet få fokus og har navn fra tittelen.
- Med fast kolonne havner ikke et element som får fokus, skjult under den.
- Mens tabellen laster, leses `loading-label` opp én gang.
- Etter et valg leses teksten om utvalget opp, for eksempel «3 valgt».
